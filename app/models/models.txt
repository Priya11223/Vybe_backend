9. PartyParticipant

This is one of the most important tables.

It represents the many-to-many relationship between User and Party.

Attribute	Type	Key / Notes
id	UUID	PK
party_id	UUID	FK → Party.id
user_id	UUID	FK → User.id
role	ENUM	host/co_host/member
status	ENUM	invited/confirmed/attended/left/removed
joined_at	TIMESTAMP	
left_at	TIMESTAMP	
created_at	TIMESTAMP	

Important constraint:

UNIQUE(party_id, user_id)

Relationship:

User N ─── M Party
        via PartyParticipant

Although the host is technically represented here too, the Party.host_id is retained because it gives us a direct and efficient way to identify the owner.

17. Notification

System notifications.

Attribute	Type

reference_type/reference_id can point to:

This is a polymorphic reference, so there isn't a traditional FK for reference_id.
